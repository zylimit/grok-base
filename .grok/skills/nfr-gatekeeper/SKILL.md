---
name: nfr-gatekeeper
description: 当需要收集非功能需求、做五性（韧性/网络安全/功能安全/隐私/可靠性）需求分析、生成 NFR-Spec、或在评审/发布前跑五性门禁时使用。
when-to-use: 非功能需求、五性、NFR、韧性、可靠性、安全需求、隐私合规、GDPR、发布门禁
---

[任务]
    **需求模式**：在 Product Spec 定稿前后，用五性清单逼问出可验证的非功能需求，生成 NFR-Spec.md（含每条的验收方式）。
    **门禁模式**：在阶段评审或发布前，对照 NFR-Spec.md 逐条给出 PASS/FAIL/WAIVED 结论，每条附证据。

[依赖检测]
    需求模式：Product-Spec.md 建议已存在（没有则先提示走 product-spec-builder，用户坚持可先做 NFR）。
    门禁模式：NFR-Spec.md 必须存在；无则先走需求模式。
    设计期深度安全/隐私分析 → 路由 threat-modeler，本 Skill 不重复做威胁建模。

[第一性原则]
    **可验证原则**：每条 NFR 必须写明"怎么证明达标"（命令/测试/演练/检查点）。写不出验证方式的 NFR 不收。
    **量化优先**：能给数字就给数字（超时 3s、可用性 99.9%、RTO 15min）；给不出就先给区间并标 [待定]，不许"尽量快""基本可用"。
    **按风险配深度**：内部小工具和资金/人身相关系统的五性深度完全不同。先问清系统的失效后果，再定各性的要求档位。
    定档追问三件套（逼出真实档位）："系统坏 1 小时，损失什么？""数据泄了，会上什么新闻？""谁半夜起来修？"
    **可度量或不写**：写不出度量方式的 NFR 条目宁可不写，也不留一句无法验收的许愿。
    **默认怀疑**：用户说"不需要考虑安全/隐私"时，列出该系统的具体暴露面反问一次；用户确认后记 WAIVED（豁免要留名）。

[五性需求清单]
    每一性按下列问题逼问，答案落 NFR-Spec：

    **韧性 Resilience（攻击/故障/灾害下的识别与恢复，抗并发冲击）**
    - 依赖清单：外部依赖有哪些？每个失效时系统行为是什么（降级/排队/拒绝）？
    - 超时与重试：每类外呼的超时值、重试上限、退避策略？
    - 冲击承压：预期峰值并发是多少？超出时限流还是扩容？限流阈值？
    - 恢复：故障后 RTO（恢复时间）/RPO（数据丢失容忍）目标？是否需要自动恢复？
    - 演练：是否要求故障注入/混沌演练？频率？

    **网络安全 Security（防未授权访问/破坏/窃听/篡改）**
    - 认证授权：谁能访问什么？匿名面有多大？权限模型（RBAC/所有权）？
    - 数据保护：传输加密（TLS）？静态加密？密钥放哪（禁硬编码，用环境/密管）？
    - 输入面：所有外部输入点列表？各自的校验策略（allowlist 优先）？
    - 审计：哪些操作要留审计日志？留多久？
    - 依赖安全：第三方依赖审计方式（npm audit / cargo audit / pip-audit）？

    **功能安全 Safety（失效不伤人/不毁物/不损环境）**
    - 失效后果分级：本系统失效最坏伤害什么（人身/设备/资金/数据/仅体验）？
    - fail-safe 方向：每类失效落到哪个安全侧（停机/只读/回退默认值）？
    - 互锁：危险操作（删除/转账/物理控制）的确认、幂等、防重放机制？
    - 越界保护：输出值域是否有物理/业务边界钳制？
    - 纯软件信息系统可将本节降档为"破坏性操作防护"，但必须显式写明降档理由。

    **隐私 Privacy（收集/使用/存储/销毁合法合规）**
    - 数据清单：收集哪些个人数据？每项的用途、法律依据、必要性？
    - 最小化：哪些字段可以不收/脱敏收？
    - 生命周期：留存期限？到期销毁机制？用户导出/删除请求怎么满足？
    - 暴露控制：日志/错误信息/分析埋点是否会带出敏感字段？
    - 合规基线：适用法规（GDPR/个保法/行业规范）及其映射条款。

    **可靠性 Reliability（规定条件与时间内持续稳定无故障）**
    - 可用性目标：SLO（如 99.9%）？统计窗口？
    - 错误预算：失败率/错误率阈值？超出后动作？
    - 数据完整性：关键数据的一致性要求（事务边界、备份频率、校验）？
    - 可观测：必须有的日志/指标/告警清单？
    - 失败可见：所有关键路径错误必须上抛或告警，禁静默吞错。

[门禁模式规程]
    1. 读 NFR-Spec.md，列出全部条目
    2. 逐条执行其声明的验证方式（命令当场跑、测试当场看输出、演练看记录）
    3. 每条结论：PASS（附证据）/ FAIL（附差距）/ WAIVED（附豁免人与理由）
    4. 汇总输出五性门禁报告；有 FAIL 时给出修复路由（dev-builder / bug-fixer / arch-guardian）
    5. 门禁报告不改代码；修复由主 Agent 另派

[输出]
    需求模式 → 加载 templates/nfr-spec-template.md 生成 NFR-Spec.md，并在 Product-Spec.md 的「非功能需求」节留指针。
    门禁模式 → 输出结构化门禁报告（五性 × PASS/FAIL/WAIVED 矩阵 + 证据清单）。

[文件结构]
    ```
    nfr-gatekeeper/
    ├── SKILL.md
    └── templates/
        └── nfr-spec-template.md
    ```

[初始化]
    判断模式：无 NFR-Spec.md 或用户在谈需求 → 需求模式；用户要验收/发布/评审 → 门禁模式。
