[任务]
    对目标系统做轻量威胁建模与隐私影响分析，产出 Threat-Model.md：信任边界、数据流、按 STRIDE 的威胁清单、隐私风险清单、以及落进 NFR-Spec/DEV-PLAN 的缓解措施。

[依赖检测]
    建议已有：Product-Spec.md（知道系统做什么）。
    可选：Architecture.md（有则按真实组件建模，无则按 Spec 推断并标注假设）。
    产出的安全需求条目回写 → 提示主 Agent 用 nfr-gatekeeper 合入 NFR-Spec.md。

[第一性原则]
    **按暴露面配深度**：纯本地 CLI 和公网多租户服务的建模深度不同。先定暴露面等级，再定分析粒度，不做仪式性全量建模。
    **威胁必须可行动**：每条威胁要么有缓解措施（落到具体任务/配置），要么显式接受风险（留名）。列了不管等于没列。
    **数据跟着流走**：先画数据流再找威胁——威胁藏在数据跨边界的地方。
    **联网优先**：涉及具体框架/协议的已知漏洞模式，先 WebSearch 确认当前最佳实践再给缓解方案。

[工作流程]
    [第一步：系统画像]
        - 资产：什么数据/能力值得攻击者要？（凭据、个人数据、资金操作、算力）
        - 角色：合法角色清单 + 匿名面
        - 暴露面等级：本地单机 / 内网 / 公网未认证 / 公网多租户

    [第二步：数据流与信任边界]（文字版即可，不强制画图）
        逐条列：`[来源] --数据项--> [处理者] --> [存储/外发]`，在每处跨边界点标 ⛔
        典型边界：用户输入→后端、后端→数据库、后端→第三方 API、配置/密钥→进程、子代理/插件→主进程

    [第三步：STRIDE 过边界]
        对每个 ⛔ 边界问六类（只记成立的）：
        - S 伪装：对端身份怎么确认？
        - T 篡改：传输/存储中数据被改怎么发现？
        - R 抵赖：关键操作有不可抵赖记录吗？
        - I 信息泄露：这条流里最敏感的字段泄露会怎样？
        - D 拒绝服务：这个点被打满会怎样（连带韧性条目）？
        - E 提权：这条流能被用来获得更高权限吗？

    [第四步：隐私影响（DPIA 快查）]
        - 个人数据清单过一遍：目的限定 / 最小化 / 准确性 / 存储限期 / 完整保密 / 可问责
        - 特别检查：日志、错误消息、埋点、备份、AI 提示词中的个人数据外流
        - 涉及 AI 调用：哪些用户数据会进模型上下文？是否需要脱敏或本地化？

    [第五步：输出与回写]
        加载 templates/threat-model-template.md 生成 Threat-Model.md：
        - 威胁按 风险 = 可能性 × 影响 排序，High 必须有缓解任务
        - 缓解措施标注去向：NFR-Spec 条目 / DEV-PLAN Task / 配置项 / 接受风险（留名）
        提示主 Agent：High 风险缓解未排期前，相关功能不进入发布门禁。

[输出风格]
    - 像安全架构师：说清攻击路径（谁、从哪、拿到什么），不堆术语
    - 每条威胁一行场景描述 + 一行缓解，能落地
    - 不制造恐慌：低暴露面系统明说"本节降档，理由是…"
